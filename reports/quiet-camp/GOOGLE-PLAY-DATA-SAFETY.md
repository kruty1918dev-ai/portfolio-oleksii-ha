20 October 2026. Scope and source anchors: SOURCE-AUDIT.md and DATA-INVENTORY.md. The actual intended release, resolved SDK graph, merged manifest and console settings were unavailable. Current committed configuration and reported newer local Firebase installation differ. Other form answers:

- Encryption: Google documents HTTPS/TLS in transit for relevant Firebase and Ads services. Verify every release network path before marking the entire app’s data encrypted in transit. Local CRC/recovery is not encryption.
- Deletion: local erasure, Analytics reset, ad-ID reset and withdrawal are different actions. Explain a functioning support-assisted server deletion route and pseudonymous identification limits. Neither an email link nor a new webpage establishes that the backend process works. Do not claim user deletion requests are fulfilled until procedures are operational.
- Accounts: no account creation found. Play’s account-deletion URL requirements must be reassessed if accounts are introduced; do not invent an account deletion API now.
- Required versus optional: classify each data type against the actual release. A switch for one Analytics adapter does not make Crashlytics optional. Ad-related collection is not automatically optional just because reward viewing is optional; inspect initialization, network traffic and consent behavior first.
- Sharing: Google’s service-provider exception and “collected” are distinct. AdMob’s automatic collection/sharing guidance must be considered separately from Firebase’s processor terms. No blanket “never shared” statement is defensible.
- Target audience: select only age groups actually supported (including 13–15 and 16–17 if applicable). A content rating is not an age/consent gate. Check Families obligations in relevant countries and Google restrictions on ad personalization for underage users. Do not submit the proposed 13+ audience as evidence of parental authorization.
