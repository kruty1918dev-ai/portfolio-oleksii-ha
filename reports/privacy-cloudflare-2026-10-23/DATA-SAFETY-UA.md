# Complimentary access і Google Play Data safety — 23.10.2026

Це технічне доповнення до чинного обліку SDK, а не готова відповідь за всю гру.
Анкета має відповідати версіям, які фактично розповсюджуються через Google Play.

- Якщо випущена версія містить цей вхід, вона передає дані за межі пристрою.
  Не обирати «дані не збираються» лише через добровільність входу чи відсутність
  реєстрації. Врахувати також автоматичне поновлення збереженої сесії.
- Врахувати видані облікові дані, session token та його хеш, access-generation,
  час перевірки, IP/HMAC-похідний ключ і мережеві відомості Cloudflare.
  Пароль обробляється короткочасно, але сесії й ліміти зберігаються: весь API
  не можна оголосити лише ephemeral processing.
- Зіставити стійкі/сесійні ідентифікатори з категорією «Device or other IDs» за
  фактичним використанням. «User IDs» залежить від того, чи ідентифікує виданий
  username конкретного користувача; спільний review-login сам по собі цього не доводить.
  Не заявляти збір місцезнаходження цим API лише через IP: код не визначає геопозицію.
  Обробку рекламними SDK оцінювати окремо.
- Мета API — функціональність доступу та запобігання шахрайству/безпека.
  Користування цим доступом необов’язкове для базової гри. Це не згода на Analytics,
  crash uploads або рекламну персоналізацію.
- Передача сервісному постачальнику може мати виняток із «sharing» лише за
  відповідності умовам Google та фактичним договорам/цілям. Це не скасовує «collection».
  Не позначати всі операції Cloudflare або Google як «not shared» автоматично.
- Sign out і видалення локальних даних не видаляють серверну сесію; privacy contact
  приймає запити з пропорційною перевіркою. Не обіцяти миттєвого серверного видалення
  з усіх резервних копій або індивідуального відкликання спільного акаунта.

Перед поданням ще потрібні фактична Android-збірка й перевірка активних SDK,
шифрування всіх каналів, договірних ролей, видалення та узгодження з глобальною
анкетою активних версій. Політика сама по собі не підтверджує ці відповіді.
